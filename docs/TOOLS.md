# Инструменты MCP-сервера MapAiMine

Всё, что видит нейросеть. Колонка «RCON» — работает ли инструмент без плагина.

## Диагностика и каталог

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `mapaimine_status` | ✅ | транспорт, версия сервера, миры, лимиты, размер библиотеки. **Вызывать первым** |
| `mapaimine_guide` | ✅ | регламент работы для агента (тот же текст, что в скилле) |
| `reconnect` | ✅ | переподключиться к серверу и перечитать `content/` без перезапуска клиента |
| `list_styles` | ✅ | каталог стилей, фильтры по сезону и тегу |
| `get_style` | ✅ | полная палитра стиля по ролям + настройки поселения |
| `list_blueprints` | ✅ | каталог построек, фильтры по категории и размеру |
| `get_blueprint` | ✅ | метаданные постройки и ASCII-предпросмотр слоёв |
| `list_structures` | ❌ | снятые через `capture_region` структуры |

## Разведка мира

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `survey_area` | ❌ | **глаза агента**: карта высот ASCII, поверхность, биомы, вода, ровность, `suggestedBuildY` |
| `probe_blocks` | ❌ | точечное чтение блоков (до 1024 точек) |
| `list_materials` | ❌ | реальный список блоков этой версии сервера |
| `validate_blocks` | ❌ | проверка id блоков с подсказками по опечаткам |

## Мир и сервер

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `create_world` | ❌ | новый мир: `normal` / `flat` / `large_biomes` / `amplified` / `void` |
| `configure_world` | ✅ | время, погода, сложность, PvP, gamerules; `applyStyleEnvironment` берёт настройки из стиля |
| `set_spawn` | ✅ | точка спавна мира; `safe:true` подложит платформу |
| `set_world_border` | ✅ | центр и размер границы мира |
| `teleport_player` | ✅ | телепорт игрока к постройке |
| `broadcast_message` | ✅ | сообщение в чат всем |
| `run_command` | ✅ | произвольная консольная команда (**не откатывается**) |

## Строительные примитивы

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `fill_region` | ✅ | заливка области; режимы `replace/keep/hollow/outline/destroy`, фильтр по блокам |
| `place_blocks` | ✅ | явный список блоков с сохранением порядка |
| `draw_shape` | ✅ | `sphere` (в т.ч. эллипсоид), `cylinder`, `cone`, `pyramid`, `torus`, `line`, `walls` |
| `terraform` | ❌ | `flatten`, `smooth`, `raise`, `terrace`, `clear` |
| `paint_surface` | ❌ | покраска верхнего слоя земли (по колонкам) |
| `scatter_props` | ❌ | естественный рассев травы, цветов, деревьев, камней, снега |
| `place_sign` | ✅ | табличка с текстом |
| `spawn_entity` | ✅ | житель, торговец, животное, моб |

## Генерация

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `build_blueprint` | ✅¹ | поставить постройку из каталога в выбранном стиле, с поворотом и подготовкой площадки |
| `plan_settlement` | ✅ | посчитать план посёлка и показать сверху в ASCII, **не меняя мир** |
| `generate_settlement` | ✅¹ | **главная фича**: деревня / город / замок / лагерь / ферма / порт целиком |
| `decorate_area` | ❌ | «навести вайб» стиля на участок: земля, трава, деревья, камни, снег |
| `build_showcase` | ✅¹ | один дом в нескольких стилях в ряд с табличками — для выбора вайба |
| `build_structure` | ❌ | поставить снятую ранее структуру (с поворотом) |
| `capture_region` | ❌ | снять постройку игрока в файл |

¹ в RCON-режиме работает, но требует явного `y` (подготовка площадки и озеленение недоступны).

## Управление задачами

| Инструмент | RCON | Назначение |
|---|:--:|---|
| `job_status` | ⚠ | прогресс фоновой стройки (в RCON всё выполняется синхронно) |
| `cancel_job` | ❌ | остановить стройку |
| `undo_last` | ❌ | откатить последнюю (или указанную) операцию |
| `list_undo` | ❌ | история доступных откатов |

## Соглашения

**Координаты.** Везде абсолютные блоки мира. `from`/`to` включительные, порядок углов любой.
Для площадных инструментов (`paint_surface`, `scatter_props`, `decorate_area`) координаты
задаются парой `[x, z]` — высота определяется по колонке.

**Высота `y` у построек** — это Y **поверхности земли**, на которую здание встаёт.
Фундамент достраивается вниз сам. Если `y` не указан — берётся из разведки.

**Блоки** — строки вида `minecraft:oak_stairs[facing=north,half=bottom]`.
Префикс `minecraft:` можно опускать. Там, где принимается `block`, можно передать
взвешенный набор — постройка перестаёт выглядеть «штампованной»:
```json
{ "choices": [ { "block": "minecraft:cobblestone", "weight": 6 },
               { "block": "minecraft:mossy_cobblestone", "weight": 2 } ] }
```

**Стили и роли.** Блюпринты не знают про блоки — они оперируют ролями
(`wall_primary`, `roof_primary`, `window`, …). `paletteOverrides` позволяет подменить
отдельную роль, не создавая новый стиль:
```json
{ "paletteOverrides": { "roof_primary": "minecraft:deepslate_tiles" } }
```

**Детерминизм.** Один и тот же `seed` при тех же параметрах даёт тот же результат.
Меняй `seed` для другого варианта, меняй координаты для переноса.

**`dryRun: true`** — оценка объёма без изменения мира. Есть у всех строительных инструментов.

**Отмена.** Каждая стройка возвращает `undo=` в отчёте. Крупные стройки уходят несколькими
пакетами — тогда `undo_last` нужно вызвать столько раз, сколько указано в отчёте.

## Проверка перед релизом

```bash
cd mcp-server
npm run validate:content                            # оффлайн: схемы, роли, размеры слоёв
npm test                                            # оффлайн: резолвер, геометрия, генератор
MAPAIMINE_TOKEN=... node scripts/verify-blocks.mjs  # онлайн: все блоки всех построек × стилей
MAPAIMINE_TOKEN=... npm run e2e                     # онлайн: все инструменты по очереди
```

`verify-blocks` рендерит каждую постройку в каждом стиле и спрашивает у сервера, существуют ли
получившиеся блоки. Это ловит выдуманные id, не строя ничего в мире.
